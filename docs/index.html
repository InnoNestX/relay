Principles

  1. The supervisor dispatches, never executes.
  2. One owner per external write channel — chat, defect system, knowledge base, code/deploy.
  3. Judge against the latest requirement — pass, file, or escalate.
  4. Conclusions live in an online report; issue numbers stay in sync in three places.
  5. Testing never queues — scale out parallel helpers; testers make their own data.
  6. Security red lines override everything.
  7. Every delivery passes the scoring gate.

The scoring gate

1 · Follow-the-flow check (hard gate). Verify every key step exists and is in order. If not, force the flow from the missing step — before any score.

2 · Score out of 100 against the rubric (templates/scorecard.md), one line of evidence per row.

3 · Verdict. score ≥ PASS_SCORE → pass below → optimize & re-run The threshold is configurable; default 80.

Install

GitHub repo Docker Hub image ClawHub skill & plugin Per-tool integrations

Claude Code plugin

/plugin marketplace add InnoNestX/relay
/plugin install relay@relay
# then: /relay-start <requirement>   ·   /relay-score

MCP (Cursor, Claude, any MCP client)

{ "mcpServers": { "relay": {
    "command": "docker", "args": ["run","-i","--rm","xuxuclassmate/relay"] } } }

Docker / local

docker run --rm xuxuclassmate/relay list
docker run -i --rm xuxuclassmate/relay            # MCP over stdio
# or local:
node server/cli.mjs list   ·   node server/cli.mjs score

ClawHub

clawhub install relay        # skill
clawhub package explore relay # plugin (OpenClaw package)

GPT · Gemini · Grok · DeepSeek · Muse · any model

Each tool has a ready-made integration under plugins/ (chatgpt, gemini, grok, cursor, claude-code, mcp). Paste plugins/system-prompt.md as the system prompt / custom instructions / Gem, then optionally add the MCP server — or export the whole pack with relay install generic --dir ./relay-pack.
