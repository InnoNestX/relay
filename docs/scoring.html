The backstop兜底机制

Scoring gate打分门禁

First ask “did it follow the flow?”, then “how well (the score)?”. The first is a hard gate; the second decides whether to re-run.先问“有没有按流程走”,再问“走得好不好(分数)”。前者是硬门禁,后者决定是否重跑。

1 · Follow-the-flow check (hard gate).流程符合性检查(硬门禁)。 Verify every key step exists and is in order (dispatch with the user's words → cases reviewed before saving → testers made their own data → per-step evidence → online report with synced IDs → defects filed + notified → no red lines). If a step is missing or out of order, force the flow from that step before scoring.核对每个关键环节是否齐全且顺序正确(派单带用户原话 → 评审通过才落库 → 测试自己造数 → 逐条证据 → 在线报告且编号三处同步 → 提单并通知 → 无红线)。缺失或乱序就从该环节强制重走,再打分。

2 · Score out of 100按百分制打分 against the rubric below, one line of evidence per row.对照下方评分卡,每项写一行依据。

3 · Verdict.判定。 score ≥ PASS_SCORE → pass below → optimize & re-run Threshold configurable in config; default 80.阈值在 config 可配,默认 80。

The rubric (100 points)评分卡(满分 100)

#Dimension维度Weight权重Full-score criterion满分标准
1Dispatch & authorization派单与授权15Clear breakdown; dispatch carries the user's words + time, scope and boundaries.拆分清晰;派单带用户原话+时间、范围与边界。
2Case quality用例质量15md+json+visual trio complete; stored only after review passes.md+json+可视化三件套齐全;评审通过后才落库。
3Data-fabrication compliance造数合规10Prefer the designated data project; restore config when done.优先调用指定造数项目;用完配置改回。
4Execution & judgment执行与判定20Per-case evidence, headless-first, judged by the latest requirement.逐条证据、无头优先、按最新需求判定。
5Reporting & sync报告与同步15Online report; IDs synced across chat/report/defect; clickable links.在线报告;编号三处同步;可点链接。
6Defects & notification缺陷与通知10Four-question minimalist ticket + severity mapping; notify right after filing.提单四问+严重度映射;提完即通知。
7Security red lines安全红线15No credentials in code/KB; redaction; deploy only when authorized.凭证不入代码/库;脱敏;授权才部署。

Example (fictional)示例(虚构)

A “library loan due-date reminder” requirement: Mia executes, Leo stores defects, Ava notifies dev Sam. Report not synced + defect not notified → 70 < 80 → list the lost points, do the fixes (sync IDs, send the notification), re-run those two steps, re-score until ≥ 80.虚构的「图书馆借阅到期提醒」需求:Mia 执行、Leo 落库、Ava 私信研发 Sam。若报告未同步 + 缺陷未通知 → 70 < 80 → 列扣分项、补做(同步编号、补发通知)、重跑这两环、重新打分直到 ≥ 80。
